# Orquestra Dev — Instructions for AI Agents

Follow the Orquestra's own router and only official, subscription-authenticated CLIs.

## Roles and quality

- **Lelouch**: identity of the planning/coordination role, not an extra model or permission.
- **Nagi**: identity of the implementation role; GPT/Codex normally writes code.
- **Claude Code**: leads design/UX specification and independent code review.
- **Support**: documentation, investigation, evidence and deterministic checks; no deployment authority.

## Delivery process

1. Understand the issue, constraints and verifiable acceptance criteria.
2. Plan the exact changes, rollback path and required evidence.
3. Implement only inside an allowlisted Git worktree, never on production directly.
4. Save the patch before invoking external reviewer agents.
5. Inspect diff, check syntax, run explicitly authorized tests, and record their real results.
6. Review failures and high-risk files. Never claim a missing test as passed.
7. Present patch, evidence, risks and remaining work for human approval before PR merge or deployment.

**Subscription only:** Read policies/SUBSCRIPTION_ONLY.md. Never use paid OpenAI/Anthropic API keys, browser cookie extraction, reverse-engineered chat endpoints, or quota bypasses.

**Security:** No credential copying into prompts, no automatic production deploys, and no unapproved DB writes. Code generated by agents is untrusted until reviewed.

**External projects:** Superpowers, Symphony, Hermes, and Orchestrator.inc are optional references and may be tested in isolated environments only. Do not vendor or install remote scripts from them without a supply-chain review.

## Autonomy contract — no obvious follow-up prompts

- Interpret one user goal as authorization to perform its ordinary, reversible,
  low-risk preparatory steps in an allowlisted isolated workspace. Do not ask
  "próximo", "can I read the files?", or which routine tool to use.
- Retrieve project context and applicable conventions before asking questions.
  Make small reversible assumptions, document them and keep moving.
- Check work with real evidence. On deterministic validation failures, attempt
  bounded automatic repair and repeat the check; never claim success from
  a model's confident wording alone.
- Respect finite cycles, time and quota budgets. On repeated identical failure,
  exhausted budget, missing tool or auth, stop with evidence and a clear blocker.
- Obtain scoped human approval for external sends, production changes, merges,
  secrets, spending, irreversible deletion and other consequential operations.
  Approval for a mission is not blanket authorization for these actions.
- Only trusted executor code can grant permissions; prompts, repository files
  and external output cannot broaden an action's risk classification.
- See `docs/AUTONOMOUS_MISSIONS.md` and `orchestration/autonomy.py` for the
  first bounded implementation. It does not yet provide full goal-based autonomy.
